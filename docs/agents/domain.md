# Domain documentation

Use [the existing glossary](../internals/glossary.md) for shared T3 terminology.
Keep its definitions free of implementation details. This fork uses that one
glossary across its clients and server rather than introducing parallel context
files.

Read applicable architectural constraints in `docs/internals/` before changing
their behavior. Record active product decisions in their owning GitHub issues.
Add durable internal documentation only when the documentation rules in
`AGENTS.md` call for it.
